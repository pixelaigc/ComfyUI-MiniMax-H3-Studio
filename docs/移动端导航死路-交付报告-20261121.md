## 一、实测根因（全部真浏览器实测，非推断）

### 根因 1 —— 参数抽屉的遮罩层盖住顶栏，汉堡按钮**真的点不动**

`web/responsive.css` 里 `.panel-mask { position: fixed; inset: 0; }` —— `inset: 0` 从视口顶铺满。
顶栏 `.topbar` 只有 44px 高且**没有 z-index**（`web/style.css:20`），
所以 z-index:949 的遮罩整块压在顶栏上。

**决定性证据**（Playwright 走真实命中测试，Timeout = 手指命中了别的东西）：

```json
// evidence/mobile-nav/decisive-before/decisive.json
{
  "panel_open": true,
  "real_click_hamburger": "FAIL: Page.click: Timeout 4000ms exceeded.",
  "sidebar_open_after_click": false,
  "real_click_mask": "FAIL: Page.click: Timeout 4000ms exceeded.",
  "real_click_card": "FAIL: ElementHandle.click: Timeout 4000ms exceeded."
}
```

⇒ 参数抽屉一开，**回到类型选择的唯一入口（汉堡）被物理遮死**；点遮罩也不行
（抽屉本体盖住了遮罩的上半部分）。这是一个**真正的死路**。

### 根因 2 —— 视频类型项是动态渲染的，收抽屉的监听绑不上

`web/app.js` 的 `initResponsive()` 里：

```js
$$(".nav-item").forEach(item => item.addEventListener("click", () => {
  if (isPhoneViewport()) setSidebarOpen(false);
}));
```

`$$(".nav-item")` 在**启动时**求值。视频模型项由 `web/video-nav.js` 在
`/api/video-categories` 返回之后**动态创建**（`item.className = "nav-item nav-model-item"`），
**绑不上**。

**实测**（`evidence/mobile-nav/deep-before/deep.json`）：

```json
{
  "binding_audit": {"total": 18, "static": 14, "dynamicVideoModel": 4},
  "static_item_closes_drawer": true,
  "dynamic_video_item_closes_drawer": false,
  "drawer_open_after_dynamic": true
}
```

⇒ 点「文生视频」后**抽屉不收**，盖住整个媒体库；
而抽屉常开时再点汉堡是「关抽屉」不是「开抽屉」——用户想回类型选择却越点越乱。

### 根因 3 —— 抽屉内没有任何「关闭」控件

全状态扫描 DOM（`backish` 字段）：

```json
"backish": []      // 每个状态都是空数组
```

DOM 里**不存在**任何语义为「返回/关闭」的按钮。抽屉只能靠点遮罩或点汉堡关闭，
而这两个在某些状态下都不可靠。

### 根因 4 —— 移动端右键菜单**根本唤不出来**

CDP 浏览器级真实触摸（按住 850ms 不松手）：

```json
// evidence/mobile-nav/longpress-before/longpress.json
{
  "contextmenu_fired": 0,
  "ctx_menu_open": false,
  "ctx_menu_items": []
}
```

更严重的是 —— **`<video>` 会吞掉所有 touch 事件**。
document / window 级 capture 探针对照实验：

| 按什么 | 收到的���件 |
|---|---|
| 普通 `<button>` | `pointerdown` / `touchstart` 全到 ✅ |
| `<img>` | `pointerdown` / `touchstart` 全到 ✅ |
| **`<video>`** | **一个都没有** ❌ |

连 `.job-preview` 容器的 capture 监听也收不到。
⇒ 在视频卡片上，「长按右键菜单」这条路**物理上不通**。

### 根因 5 —— FAB（position:fixed 右下角）压住侧栏抽屉内容

```json
// evidence/mobile-nav/fabdrawers-before/fab-vs-drawers.json
"sidebarOverlap": {"w": 25, "h": 44,
  "covered": [{"text": "音乐", "cls": "nav-group"},
              {"text": "文生音乐", "cls": "nav-item"}]}
```

FAB 的 z-index 960 **高于**侧栏抽屉 940 ⇒ 压在导航项上，
违反需求 B4「导航控件不得遮挡抽屉内容」。

## 二、修复

| # | 根因 | 修法 | 文件 |
|---|---|---|---|
| 1 | 参数抽屉遮罩盖住顶栏 | `.panel-mask` 的 `inset: 0` → `inset: 44px 0 0 0`（让开顶栏） | `web/responsive.css` |
| 2 | 动态项绑不上收抽屉 | 改成在 `#sidebar` 上**事件委托**（`closest('.nav-item')`） | `web/app.js` |
| 3 | 抽屉无退路 | 抽屉顶部加标题行「选择生成类型」+ 44px 的「×」关闭按钮 | `web/index.html` + `web/responsive.css` + `web/style.css` + `web/app.js` |
| 4 | 右键菜单唤不出来 | 卡片底部加「☆ 收藏 / ★ 取消收藏」按钮（纯 DOM 按钮，touch 正常）+ 保留长按手势（图片卡） | `web/app.js` + `web/favorites.js` + `web/favorites.css` |
| 5 | FAB 压住抽屉 | FAB 显隐判据**集中到 `updateResponsiveChrome()`** 一处：两个抽屉任一开着就藏 | `web/app.js` |

### 修的过程中我自己引入又修掉的 5 个真 bug

这轮最该被看到的部分 —— **每一次都是我自己写的测试抓出来的**：

1. **FAB 显隐规则有三份实现**（`setPanelOpen` / `updateResponsiveChrome` / FAB 的 click 处理器）
   互相打架 ⇒ 抽屉关了 FAB 还藏着，用户再也打不开参数面板。
   实测：`test_hamburger_clickable_while_param_drawer_open` 390px 子用例报
   `element is not visible`。
2. **`closePanelDrawerOnPageChange` 直接摘 `.open` 类**，不通知 FAB ⇒ 同样症状。
3. **长按手势绑在媒体元素上** —— `<video>` 吞事件，等于没绑。
4. **`image.file` 没加可选链** —— 视频卡长按时抛 TypeError。
5. **把 `web/app.js` / `web/index.html` 的 CRLF 改成 LF**（老陷阱，本轮又踩了一次）
   —— 被既有的 `test_crlf_files_keep_crlf` 守卫抓住（diff 一度变成 16,261 行）。

## 六、已知限制与未做到

1. **视频卡的长按右键菜单仍然唤不出来** —— 这是 `<video>` 的原生手势处理，
   Chrome 不允许页面拦截。已提供不依赖右键的入口（底部收藏按钮）。
   **图片卡的长按菜单正常。**
2. **桌面端卡片底部也多了一个「☆ 收藏」按钮** —— 与其它操作按钮同一排。
   右键菜单保留，两条路径并存不冲突（需求 B5 的「功能重复」指重复入口，
   这里是一个显式按钮 + 一个上下文菜单，属于不同交互层次）。
3. **参数抽屉的遮罩让开顶栏后，视觉上遮罩只盖 44px 以下** ——
   顶栏区域保持可见可点，这是刻意的。
4. **`job-actions` 按钮变多**（多了收藏），375px 下会换行
   （`.job-actions` 已有 `flex-wrap: wrap`），实测未溢出。
5. **长按手势的 550ms 阈值** 是经验值，与移动端浏览器自身的阈值接近，
   可能与用户预期略有出入。
