## 一、需求与落地位置

### 目标 1：所有媒体引用必须先进入素材库

用户要求：首尾帧 / 参考生等功能的图片 / 音频 / 视频引用，与「图片编辑」保持一致 ——
外部素材必须先进入素材库，界面只能从素材库挑选并引用，**不允许功能直接引用外部文件路径**。

**现场核实结论**：改动前 `flf`（首尾帧）/ `r2v`（参考生视频）面板
仍然存在「本地文件直传」入口 —— 槽位渲染器创建 `<input type="file">`，
提交体用 multipart 的 `file_first` / `file_last` / `file_ref` / `file_refvid` /
`file_refaud` 直接把本地文件路径交给服务端。`i2i_qwen` / `i2i_h3image`
（「图片编辑」）**早已**有这条约束（`code="ref_must_come_from_library"`），
本轮把前两者对齐。

### 目标 2：种子仅允许正整数

用户实测：非数字种子 → 用户只看到
`✕ 生成失败（服务端未能给出具体原因）。请稍后重试；若反复失败，请查看服务端日志，或改用「复用参数」重新生成一段。`

**根因**（现场核实）：种子**一路不校验**地流到 worker ——
`workflows.py:339` 取 `params.get("seed")`，`workflows.py:380` 执行 `int(seed)`，
ValueError 被 worker 捕获后只剩一句兜底文案（`server.py:1003` `_GENERIC_FAILURE_REASON`）。

本轮把校验提前到「提交前」与「服务端入口」，非法种子**明确拦截并给中文原因**。

### 目标 1：媒体引用

| 场景 | 修复前 | 修复后 |
|---|---|---|
| flf 界面选首帧 | 点空槽位弹**系统文件选择框** | 点空槽位直接开**素材库选择器**（`categories:["image"]`） |
| flf 界面选参考视频 | 同上（本地 .mp4 直传） | 素材库选择器 `categories:["video"]` |
| 拖媒体库结果到槽位 | fetch 成 blob → multipart 直传 | 提示「该媒体尚未入库素材库，请先上传到素材库后再引用」 |
| 提交体 | `fd.append("file_first"/"file_last"/"file_ref"/"file_refvid"/"file_refaud", …)` | 无任何 `file_*` |

## 七、已知遗留

1. **素材库不可用时**：素材库挂载点（`/mnt/usb2t/asset_library`）掉线时，
   `asset_ref_guard.lookup_asset()` 查不到素材 → 引用**被拒**（返回
   「尚未入库素材库」）。这是**有意的**：放行等于「没有素材库也能引用外部路径」，
   正好违反需求。代价是素材库掉线期间无法用素材引用功能。
2. **媒体库结果不能直接拖进槽位**：必须先「入库素材库」再拖。用户要求是
   「媒体必须先入素材库」，这是该要求的**直接后果**，不是缺陷；但操作路径
   变长了（媒体库卡片右键「添加到素材库」→ 素材库拖到槽位）。
3. **历史任务不受影响**：老任务的 `params` 里仍躺着 `first_frame: "img-xxx.png"`
   这类直传路径（现场统计 flf/r2v 共 104 条历史任务，其中 18 条 flf 是纯直传）。
   本轮只拦**新建任务**，老任务的**重放**路径（worker 里读 `params["first_frame"]`
   去 UPLOAD_DIR 找文件）**没有**改 —— 改了会让老任务永久无法复用。
   若需要清理，需另开一轮（涉及 worker 侧的历史任务重放兼容）。
4. **`prepare_job_params` 里的 `file_*` 接收分支保留未删**：multipart 解析那几行
   仍在（`server.py` 的 `api_create`），只是 flf/r2v 分支现在会**明确报错**。
   保留是为了让老客户端收到**中文原因**而不是 aiohttp 的 415/400 裸错误。
   `i2i_qwen` / `i2i_h3image` 的直传拒绝逻辑**原样保留**（既有约束，未弱化）。
5. **`state.files` 字段已从前端 state 移除**，但 `web/app.js` 里
   `resetSlotsForMode` 的测试替身（`tests/test_slot_state_reset.py`）仍注入该字段
   —— 那是测试夹具的历史包袱，已在测试里注明，产品代码不再触碰它。
