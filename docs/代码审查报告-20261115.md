**位置**

```
 {"tag":"B","title":"骨架占位模型 · 8步","color":"rgba(0, 0, 0, 0)"},
 {"tag":"B","title":"未使用 LoRA",...},{"tag":"B","title":"res_multistep",...},

```
模态框扫描同样命中（`mossLayoutModal` / `agManageModal`）。

**为何会显示给用户**
`skeletonJob()` 造的假任务被 `jobCard()` **复用**渲染（刻意设计，保证「骨架→真实卡片」盒模型逐像素一致）。CSS 用 `color: transparent` 把文字涂掉，但：
- `title` 是**浏览器原生 tooltip**，悬停即以浮层显示，与颜色无关；
- DOM 文本节点可被复制、会被读屏软件朗读。

实测补充（重要，避免夸大）：`document.elementFromPoint()` 命中的是 `.jobs-grid` 而非骨架元素本身 —— 因为 `.job-skeleton { pointer-events: none }`（`web/style.css:383`）**会挡住原生 tooltip 触发**。所以「悬停弹出假 tooltip」这条在当前 CSS 下**不成立**；真正成立的是：
1. 文本节点确实在 DOM 里（`Ctrl+A` 复制实测：`copiedHasSkeletonText: true`，片段 `"骨架占位模型 · 8步"`）；
2. `title` 属性仍在 DOM（可被读屏/自动化/「查看源代码」读到）；
3. 首屏即出现 12 张，是最高频路径。

**修复**
- `model_label` → `"载入中"`
- `prompt` → `"正在载入任务内容，模型与参数稍后显示，此处的临时文字仅用于对齐布局。"`
- `renderGridSkeleton()` 新增 `card.querySelectorAll("[title]").forEach(el => el.removeAttribute("title"))`

**回归测试**：`tests/test_visible_text_pollution.py::TestSkeletonCardText`（3 条）

### 3.2 B-1 【Critical】flf/r2v 提交尺寸被陈旧 state 覆盖（**本轮最重要发现**）

**位置**：`web/app.js:3168-3172`

**问题**
修复③ 把首尾帧/参考生视频面板改成与文生视频共用一套面板后，提交链路里留下一段**无条件覆盖**：
```js
if (shared.width)  params.width  = shared.width;   // 3136：用户真实选择
if (shared.height) params.height = shared.height;
...
const legacySize = currentLegacyVideoSize();        // 3168：旧面板的陈旧 state
if (legacySize) {
  params.width  = legacySize.width;                  // ← 把上面覆盖掉了
  params.height = legacySize.height;
}
```
`currentLegacyVideoSize()` 读 `state.res` / `state.aspect`，而这两个字段**全仓从未被写过**：
```
=== state.res ===   (0 处赋值)
=== state.aspect ===  (0 处赋值)
```
只在 `state` 初始化时定死 `"544p"` / `"16:9"` → 恒定算出 **864×480**。

**根因**：这正是那段注释自己要修的毛病（「面板说一套、产物另一套」）的翻版 —— 修复③ 修好了「不传 width/height」，却又被后加的一段覆盖回去。

**现场证据（node 跑真实实现）**
```
currentLegacyVideoSize() for flf = {"width":864,"height":480,"megapixels":0.4}
after shared assignment  : 1088x608
after legacySize override: 864x480
BUG CONFIRMED: true
```

**真实浏览器 before/after 对照（决定性证据）**
| 端 | 面板选择 | 实际提交的 width×height | 判定 |
|---|---|---|---|
| **8190（修复前）** | 1088×608 | **864×480** ❌ | 面板说一套、产物另一套 |
| **8191（修复后）** | 1088×608 | **1088×608** ✅ `resolution: "608p"` | 与像素一致 |

**修复**
删掉无条件覆盖，`legacySize` 只用于反算 `resolution` 档位标签（与服务端 `reso_label` 同口径），**不再回写 width/height**：
```js
const legacySize = currentLegacyVideoSize();
if (legacySize) {
  params.resolution = legacyTierForPixels(
    Number(params.width) || 0, Number(params.height) || 0);
}
```
共享面板未就绪时，兜底分支（`else`）本来就已用 `currentLegacyVideoSize()` 填 width/height，**功能不丢**。

**回归测试**：`tests/test_flf_r2v_size_not_overridden.py`（4 条 + 4 subtest）
用 node **真跑** app.js 里抽出的 `legacyVideoSize`/`legacyTierForPixels` + 从源码动态抽取的覆盖分支，复刻提交链路的赋值顺序 —— 而不是抄一份到测试里（抄一份就测不到 app.js 的改动）。
