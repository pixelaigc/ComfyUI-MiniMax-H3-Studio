模态框扫描同样命中（`mossLayoutModal` / `agManageModal`）：
```

[mossLayoutModal] TEXT <B> :: 骨架占位提示词，用于让元信息区高度与真实卡片保持一致，长度对齐真实内容。
[mossLayoutModal] ATTR:title <B> :: 骨架占位模型 · 8步
```

**为何会显示给用户**
`skeletonJob()` 造的假任务被 `jobCard()` **复用**渲染（刻意设计，为保证「骨架→真实卡片」盒模型逐像素一致）。`model_label` 与 `prompt` 原样进入 `<b>` 文本节点和 `title` 属性。
CSS（`web/style.css:384-389`）用 `color: transparent` 把文字涂掉 —— 但：
- `title` 是**浏览器原生 tooltip**，悬停即显示，与颜色无关；
- DOM 文本节点可被复制、可被读屏软件朗读。

**实测修正**：我最初按「原生 tooltip 悬停可见」判 severity，实测发现骨架卡有 `pointer-events: none`（`style.css:383`），`document.elementFromPoint` 命中的是 `.jobs-grid` 而非 title 元素 → **原生 tooltip 实际被 pointer-events 挡住，不会弹出**。
所以真实用户可见路径是：**① 文本节点（Ctrl+A 复制可带走）；② 读屏软件可读出**。severity 维持 High（首屏必现、且是用户可见产物），但**「悬停弹 tooltip」这一条不成立**，已按实测修正本报告描述。

**修复方式**
1. `model_label` → `"载入中"`；`prompt` → 中性占位（不含「骨架」「占位」等开发者措辞）；
2. `renderGridSkeleton()` 里对骨架卡整体 `removeAttribute("title")`（骨架卡的 title 全是占位值，无信息价值）；
3. 保持 `color: transparent` 与 `aria-hidden="true"` 不变（它们解决的是布局抖动与可访问性暴露，不是文案污染）。

**无测试依赖**：`grep -rn "骨架占位模型\|骨架占位提示词" tests/` → 0 命中。

**修复后实测（8190）**
```

Ctrl+A 复制正文含「骨架」：false

### C-3 【High】`/files/` 路径穿越（%2F 编码可绕过） —— ✅ 已修

**位置**：`server.py:8558-8561`

**问题**

```
