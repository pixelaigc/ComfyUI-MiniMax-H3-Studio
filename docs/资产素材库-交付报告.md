## 4. 需求逐条对照

| 需求 | 实现 | 验证 |
|---|---|---|
| ① 存储位置 | `/mnt/usb2t/asset_library/{originals,previews,derived,tmp,trash}`，原件按 sha256 两层分目录；启动自检挂载点（`/proc/mounts` + `st_dev` 对比）+ 可写探针 + 空间安全线；不可用时返回明确错误且不删任何东西 | 单测 `test_mount_detection_*`；实测未挂载路径判 False、已挂载判 True |
| ② Web 上传 | 多选 + 拖拽 + 逐文件进度；服务端流式落盘（256 KB/块，不整文件进内存）；扩展名白名单 + 大小上限；**不二次转码** | 浏览器实点上传 3 个真实文件；原件与源文件 `cmp` 全部 IDENTICAL |
| ③ 元数据 | 类型/格式容器/尺寸/时长/大小/编码（图像视频音频）/采样率/声道/来源/创建时间/标签/分析文本/分析时间/所用模型/缩略图路径/内容哈希 | 实测：mp4 → 480×852, 12.31s, 29.98fps, h264/aac, 44100Hz, 2ch；mp3 → 150.05s, mp3, 32000Hz, 2ch |
| ④ 用户标签 | 增删改查 + 重命名 + 按标签筛选 + 名称/类型/来源/时间筛选 + 分析文本全文检索 | 浏览器实点加标签后卡片立即显示；检索「菱形」命中分析文本 |
| ⑤ 模型分析 + 纠错 | 复用「本地模型配置」的默认多模态 Provider；中文分节详尽描述（服装/发型/表情/配饰/场景/光线/构图…）；视频抽帧密度可调；**多轮纠错**带历史版本 | 真实调用本地 Qwen 多模态：图片 19s 出 1523 字描述；视频 25s 抽 6 帧按时间线描述；纠错后生成第 3 版且文本含「菱形」 |
| ⑥ 媒体库右键入库 | 覆盖**有批次**（批次缩略图）与**无批次**（卡片预览图/视频）；携带 job_id + batch_id + 生成参数（提示词/种子/模型/LoRA/采样器/调度器/CFG/shift） | 浏览器实点两次；DB 核对：有批次 → `job` + `job_batch` 两条引用，无批次 → 仅 `job` |
| ⑦ 引用与使用 | 任务参数面板「素材库」按钮 + `application/x-h3-asset` 拖拽引用（只存 asset_id，不复制文件）；`asset_refs` 随任务提交，worker 按槽位上传到 ComfyUI；记录引用关系与被引用次数；被引用素材删除返回 409 + 引用清单 | 浏览器实点选择器填槽成功（显示「素材库」角标）；删除被引用素材弹窗列出「任务 xxx 的产物（output）/批次 #1（output）」 |
| ⑧ 数据库与一致性 | 独立 `asset_library.db`（不碰并发任务的 jobs.db 表结构）；5 张表 `assets/asset_versions/asset_tags/asset_refs/asset_analyses` + `PRAGMA foreign_keys=ON`；删任务不删素材（引用行随任务清理，素材本体保留）；删素材前服务端强制检查引用 | 单测 `test_deleting_task_does_not_delete_asset`；实测 409 引用清单 |
| ⑨ 交付 | 前端页/抽屉/标签/分析/纠错/右键/上传进度；REST 全量；56 个新测试；真机浏览器实点 + 10 张截图 | 见下方验证证据 |

## 6. 真机验证中发现并修复的缺陷

| 缺陷 | 根因 | 修复 |
|---|---|---|
| `tags_any` / `tags_all` 永远查不到 | 入参是逗号分隔字符串，直接迭代拿到的是**单个字符**（「原神」→ `['原','神']`） | 按逗号切分；补回归测试 |
| `/api/assets/picker` 500 | SQL 把 `duration_sec` 写在 `assets` 表，实际该列在 `asset_versions` | 改子查询取当前版本值 |
| 上传时标签静默丢失 | multipart 字段顺序由客户端决定，服务端边读文件边入库 → 选项还没读到 | 改两遍：先流式落盘读完整个表单，再统一入库；前端同时把选项提前 |
| 视频/音频误判「无法解码」 | `ffprobe` 只给 `-print_format json` 不带 `-show_format/-show_streams` → 返回空对象 | 补 `-show_format -show_streams` |
| 素材选择器打不开 | 上一条的连带后果（picker 500） | 同上 |
| 视频缩略图 copyfile 失败 | 预览目标目录未创建 | `dest.parent.mkdir(parents=True)` |
| 还原后文件名变了 | `trash_path` 存的是回收站路径而非原路径 | 改存原相对路径 + 列迁移 |

## 7. 已知限制

1. **音频深度分析未接入** —— 按要求留好插拔接口，等《音频分析方案.md》结论。
2. **素材版本管理只做了数据结构**（`asset_versions` + `version_count`），未做「上传同素材自动升版本」的完整交互。
3. **素材集 / 派生 fork / 版本回滚 UI** 未实现（计划书列为第二版或可选）。
4. **全量检索用 LIKE**，未上 FTS5（计划书建议 ≥1 万条再迁）。
5. 素材库使用**独立数据库**，与 jobs.db 的关联靠 `asset_refs` 显式登记 + 应用层约束，
   未启用跨库外键（SQLite 跨库不支持）——计划书 §5.4 的跨库外键方案需改为同库才能成立。
