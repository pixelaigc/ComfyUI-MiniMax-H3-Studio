## 一、缺陷

参考素材（参考图 / 参考视频 / 参考音乐 / 首尾帧 / 参考音频）被添加到面板后
**没有移除入口**：

| 面板 | 改动前的移除入口 |
|---|---|
| 首尾帧 / 参考生视频的素材槽位（`.up-slot`） | **完全没有** —— 填满后想换掉一条，只能去素材库删素材，或切模式清空整块 |
| Qwen / H3-Image 的参考图 | 只有缩略图右上角一个很小的 `×` 按钮 |
| 参考生音乐的参考音频 | 只有卡片上一个小「移除」按钮 |

更严重的是：即便补上删除按钮，如果**只删条目**而不动编号，
界面会出现「参考 1 / 参考 3」这种空洞编号 —— 送进模型的图序与界面编号
对不上，且 H3 视频的 T8 条件节点在 `strict_prompt_tags` 模式下会**硬失败**：

```
<Picture 2> is not connected; available picture count is 1
```

## 三、移除后必须同步的三件事

1. **参考素材列表**本身少一条；
2. **同组**后面的素材**前移**（编号保持连续）——
   否则「参考 1 / 参考 3」这种空洞编号会让送进模型的图序与界面编号对不上；
3. **提示词里的占位标记**同步重写：被移除那条的标记**删掉**（不留悬空
   `<Picture N>` / `<Video N>` / `<Audio N>`），其余按新序号**单遍**替换
   （不能「先替换大的再替换小的」，会连环替换）。

### 占位语法的边界

| 模式 | 官方标记 | 编号规则 |
|---|---|---|
| Qwen 图片编辑 | `<image1>`（小写、无空格） | 按图片类型计数；多图时**强制**要求写全 |
| H3-Image 图片编辑 | `<Picture 1>` | 同上，但官方语义是「用 `<Picture N>` 引用」而非「必须引用」 |
| H3 视频（flf / r2v） | `<Picture N>` / `<Video N>` / `<Audio N>` | **按类型分别计数**：图片 → 视频（各带其背景音）→ 独立音频 |

视频模式的重写**只换数字，不改写法** —— `<image1>` 不会被改成
`<Picture 1>`（那样切回 Qwen 模式后 Qwen 的正则 `/<image(\d+)>/` 扫不到，
合法提交会被误拒）。

## 六、线上实测（8190，真实 Chromium）

| 场景 | 结果 |
|---|---|
| r2v 槽位右键 | 菜单弹出，项为「移除这个参考素材」 |
| r2v 移除「参考 1」（2 张图） | `state.assetRefs` 只剩 `ref0`（原第 2 张前移）；提示词 `A=<Picture 1> B=<Picture 2>` → `A= B=<Picture 1>`（**无悬空**）；`ref1` 槽位变回空槽 |
| Qwen 参考图右键 | 菜单弹出，项为「移除这张参考图」；移除后 `count` 2→1、序号徽标重排为 `["1"]`、提示词 `A= B=<image1>` |

| 控制台 | 全程 **0 JS 报错** |
