## 3. 本轮发现的 3 类失败 —— 全是测试脚本误判，不是产品缺陷

这一节是本轮最重要的产出。**三次「失败」都指向真实可跑的产品**，我用独立探针逐一证伪了「产品有缺陷」这个假设，然后把判据改对。

### 3.1 判据 A：平板档「回类型选择」要先 scrollIntoView

**现象**：`844x390`（390 的横屏）连续 6 腿 `exit_picker=False`。

**定位**：`fav_entry()` 为了够到左侧「收藏」入口，把 `#navScroll` 滚到了底部；之后退出探针直接探「**第一个** `nav-item[data-mode]`」—— 它此时在折叠线上方之外，探不到。

**这正是上一轮总结里点名的误判类**：「侧栏项在折叠线下需滚动」。

**独立验证**（`/tmp/probe844.py`，不依赖矩阵脚本）：

```
is_phone: False
A 不滚动: {'found': True, 'rect': {'t':151,'b':201}, 'inView': True}
B 滚动后: {'inView': True, 'hitSelf': True, 'hitCls': 'nav-item nav-model-item'}
C 再选类型: t2i          ← 真的能再选一次
```

**修正**（`28e5673`）：平板档这一支改成先 `scrollIntoView({block:'nearest'})` 再探，与同一脚本里 `select_type` 的写法一致。

### 3.2 判据 B：收藏视图的终态不能靠固定 sleep，也不能只等「第一张卡片」

**现象**：`430x932` 连续 4 腿 `cards=0`；修成「等第一张 `.job-card[data-jid]` 出现」后，`1024x768` 又失败 1 腿。

**定位**：收藏视图是**异步拉取**后渲染的（`/api/jobs?...&favorites=1`）。两个坑叠在一起：

1. 固定 `wait_for_timeout(1200)` 时请求还在飞 ⇒ 读到 0 张。
2. 改成「等第一张带 `data-jid` 的卡」后仍然不够 —— 因为**切视图是异步重渲染**（不是先清空再填），**上一个视图的卡片还在 DOM 里**，那个条件**立刻**成立；随后 grid 被清空又填上，正好在两次采样之间读到 0 张。

**独立验证**（`/tmp/probe430c.py`、`/tmp/probe1024.py`）：

```
# /tmp/probe1024.py —— 1024x768
  初始卡片: 12
  +1000ms 卡片=0 activeTab=favorites
  +2000ms 卡片=0 activeTab=favorites
  +4000ms 卡片=12 activeTab=favorites
  网络: [('status=all&favorites=1&page=1&page_size=12', 200), ...]   # 全 200
  pageerror: []                                                      # 无 JS 错误
```

⇒ 请求全 200、无 `pageerror`、`activeTab` 正确 ⇒ **纯时序问题，产品正常**。

**修正**（`dcbbb52` → `e76e695`）：终态判据 = **骨架卡消失 且 至少有一张带 `data-jid` 的真实卡片**（骨架卡 `class=job-skeleton` 且**没有** `data-jid`，是「正在加载」的标记）。

> 为什么不用「骨架屏消失」单独当终态：收藏为空时根本没有卡片，骨架屏会一直不存在 ⇒ 那个条件**立刻**成立 ⇒ 又是空转。

### 3.3 判据 C：短视口下要「扫滚动位置找可命中坐标」，不能靠 scrollIntoView

**现象**：`667x375` 连续 4 腿 `cards=0`。

**定位**：`scrollIntoView({block:'nearest'})` 把入口贴到滚动容器**上沿**，而 `667x375` 下 `#navScroll` 可视高只有 **169px**（内容 1124px），上沿正好在**顶栏（44px，z-index 高于侧栏）底下** ⇒ playwright 的 tap 报 `element is outside of the viewport`。

**先证伪「产品缺陷」**：新写 `scripts/probe_fav_reachability.py`，**先打开抽屉**再在 `#navScroll` 的各个滚动位置用 `elementFromPoint` 扫 —— **10 档全部 reachable=True**：

## 6. 变异测试（§3 项）

### 6.1 方法

`scripts/mutation_test_3guards.py`：每条变异 **破坏** 某条守卫所断言的行为 ⇒ 该守卫必须**变红** ⇒ 恢复 ⇒ 必须**重新变绿**（阴性对照）。

**纪律**：只改**产品代码**（`web/`），不改守卫本身（改守卫等于没测）；改前确认 `web/` 干净（`git status --short -- web/` 为空），恢复用 `git checkout -- web/`（会丢未提交改动，所以改前必须先 commit）。

### 6.2 结果：**4/4 咬人，恢复后 4/4 重新变绿**

| 变异 | 破坏的行为 | 目标守卫 | 咬人 | 恢复后 |
|---|---|---|---|---|
| M1 | 左侧「收藏」入口不再走 `showFavorites()`（落进兜底分支） | G1 | ✅ | ✅ PASS |
| M2 | 汉堡不再打开侧栏（`sidebar.classList.toggle("open", open)` 注释掉） | G1 | ✅ | ✅ PASS |
| M3 | 768 下收藏入口 `display:none` | G2 | ✅ | ✅ PASS |
| M4 | 收藏视图卡片不开详情（`if (state.tab !== "favorites") openDetailModal(job)`） | G3 | ✅ | ✅ PASS |

### 6.3 变异测试抓到的真实缺口（重要）

**第一轮变异时 M1 没被 G1 抓住。** 我没有把它记成「等价变异体、跳过」，而是查了两条路径的可观察差别：

- `showFavorites()` 里有 `$$(".nav-item").forEach(x => x.classList.remove("active"))` + `nav.classList.add("active")` ⇒ **导航高亮**；
- 兜底分支**没有**这两句 ⇒ 进收藏视图后入口不高亮。

⇒ 给 G1 **补上「`#navFavorites` 必须带 `active` 类」这条断言**（它正是「命名该行为的那条断言」），补完后 M1 变红。

> 这条是本轮变异测试唯一的**净收获**：一条看起来绿的守卫，其实少锁了一个可观察行为。

证据：`evidence/mobile-nav/mutation-3guards.json`

## 10. 未修项与已知限制（如实列出）

1. **视频卡长按 → 右键菜单受 `<video>` 原生手势限制**：`<video>` 元素会吞掉长按事件，长按不一定能弹出右键菜单。**本轮未修、未验证**。这是上一轮就记录的遗留项。
2. **长按阈值 550ms 是经验值**：未在真机上标定过，实际手感未验证。
3. **本轮未在真机验证**：全部证据来自 Chromium（Playwright headless + Xvfb headed）。iOS Safari 的 WebKit 行为未在本轮矩阵中覆盖 —— 上一轮曾用 WebKit 跑过一轮（`evidence/mobile-nav/realscan/`，10 个视口目录），但**那一版脚本没有「进入/退出收藏栏」这一段**，所以不能算本轮矩阵的 WebKit 证据。
4. **真机与模拟的差异**：模拟器无真实触摸压力/手势系统、无 Safari 的橡皮筋滚动、无地址栏收缩导致的视口高度变化。真机上的实际可视高度常比模拟小（如 375×667 真机可能只有 ~600px 可视）。本轮已覆盖 320×568（最窄）与 844×390 / 932×430（短高）作为近似，但**不等于真机**。
5. **核心套件在本机跑不完**：`tests/`（非 e2e）约 4107 个用例，本机 load average 常年在 15~19（另有两条任务在并发跑 pytest），多次跑到 45%~48% 就撞超时。**未取得「一次跑完」的完整数字**；已取得的是：守卫文件 **11 passed**、失败用例在**隔离运行下通过**（证明是并发争用导致的 flaky，不是产品缺陷）。详见「回归结果汇总」节。
6. **e2e 套件未全量跑**：e2e 需要真实后端（ComfyUI），本机 7 个 h3studio 实例中 4 个是旧构建。抽查的 3 个 e2e 在基线 `97e7294` 上 **3 passed in 532s**；在并发压力下同一批会失败。
7. **768 档 12 模式覆盖是本轮新增**：上一轮 768 只测了 3 个模式（t2v/t2i/t2a），本轮补齐到 12 个。
8. **`quota/minimax_quota_latest.json` 不存在**：本轮无法给出额度数字（§1.1）。
9. **本轮产品代码零改动**：所有修复都在**测试判据**。也就是说 —— **用户报的现象本身在上一轮（`edba2ef`~`97e7294`）已经修完并上线**，本轮做的是「证明它真的好了」+「把没测到的补齐」。
