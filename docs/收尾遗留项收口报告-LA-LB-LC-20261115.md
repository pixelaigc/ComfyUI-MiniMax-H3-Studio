## 3. L-C：`base_verdict` 字段补齐

### 3.1 定位

字段由两处 payload 构造产出（`h3studio/loras.py`）：`_list_loras_for_base()`（Qwen/MOSS 共用）
与 `list_z_image_loras()`。改前两处都**只从目录取**，目录没登记就是空串
→ 接口下发 **197 / 143 条为空**。

> 核实：仓库**没有**「预热」/「健康检查」HTTP 端点。`scripts/prewarm_moss_lora.py` 是离线脚本；
> `/api/system` 是队列/硬件状态。`base_verdict` 缺失的真实落点就是上述两处 payload 构造。

### 3.2 补法（按既有判定语义，绝不新增常量为 true 的假值）

新增 `_resolve_base_verdict(info, compat)`，判定**完全落在既有三条实测结论**上：

| 取值 | 条件 |
|---|---|
| `不可用` | `conversion_status == "broken"` |
| `不适配` | `compatible == false`，或 `attention_hit < 1.0` |
| `原生` / `近似适用` | 目录登记过**且**实测判定可用 |
| `已适配` | 目录没登记，但实测判定可用 |

**实测优先于目录**：目录说「原生」而实测 broken → 判「不可用」，不写「原生」。

前端同步：`web/app.js` 详情面板区分「近似适用」/「不适配」/「不可用」三档。
