## 1. 根因分析

### 1.1 BUG 1 —— 卡片 LoRA 显示错误

用户现象：卡片「LoRA」行显示 `integrated_multimodal_description: [Shot 1] ...`（一段**提示词**），而该任务实际未使用任何 LoRA。

根因是**一条链上的两个漏洞**，必须两端都堵：

#### 漏洞 1（落库端）：`agent_schema.validate_params` 的 LoRA 校验对非视频模式**完全空转**

`h3studio/agent_schema.py:1209` 原实现：

```python
lora = params.get("lora")
if lora:
    allowed = mode_loras(mode)
    if allowed and str(lora) not in allowed:   # <-- allowed 为空 -> 整个分支跳过
        issues.append(...)
```

`mode_loras(mode)` 对**图像 / 音乐模式返回空列表**（`agent_schema.py:250-254`：只有 `is_video_mode` 才有 LoRA 集合）。于是 `allowed` 为空 → `if allowed and ...` 短路 → **任何字符串都能进 `params["lora"]`**。

实测（修复前，本 worktree 内直接调用）：

```
t2v        n=1 codes=['invalid_lora']     <- 视频模式本来就拦
t2i        n=0 codes=[]                   <- 图像模式放行任意字符串
t2i_qwen   n=0 codes=[]
t2i_moss   n=0 codes=[]
t2a        n=0 codes=[]                   <- 音乐模式放行任意字符串
a2a        n=0 codes=[]
```

所以 Agent 把提示词误填进 `lora` 字段时，**任务照样建成功、照样出片**。

#### 漏洞 2（展示端）：`job_meta._legacy_video_summary` 把 `params["lora"]` **原文**当 LoRA 显示名

`h3studio/job_meta.py` 原实现：

```python
elif lora:
    out["lora_label"] = lora          # <-- 原文照抄，没有任何「这是不是 LoRA」的判断
    out["lora_name"] = str(wf.LORAS.get(lora) or "")
```

实测（修复前）：

```
job_meta.summarize("t2v", {"lora": "integrated_multimodal_description: ..."})
  -> lora_label = 'integrated_multimodal_description: [Shot 1] A cinematic shot.'
```

这段文字被原样印在卡片的「LoRA」行上。

#### 第三处同源漏洞：素材库入库端

`h3studio/asset_service.py:add_from_media_output` 原本 `params.get("lora")` **原文**照抄进 `source_meta`；前端素材抽屉把 `source_meta` 的每个键**原样印出来**（`web/assets.js:418`）→ 同样会把提示词印在「lora」那一行。

### 1.2 BUG 2 —— 卡片不显示步数等参数

卡片模板原本只有「模型 / 采样 / 步数/CFG」几行（且采样与步数混在一行、CFG 与步数挤在一起），**没有独立的步数、调度器、采样器、尺寸、时长行**，也没有地方能看完整参数。

更关键的是：这些值**分散在不同字段名里**，前端自己拼必然漏、也必然串：

| 语义 | 视频 | 图像 | 音乐 |
|---|---|---|---|
| shift | `shift_video` + `shift_audio` | `shift` | — |
| 时长 | `duration` | `duration` | `max_duration` |
| 步数 | `steps`（旧路径还要按 lora 档位给默认值） | `steps` | `steps` |
| 尺寸 | `width`/`height`，但**产物实际像素**才是卡片该显示的 | 同左 | — |

---

## 2. 设计原则

1. **唯一真源在服务端**。前端**不自己猜**「这个任务的步数是多少」。服务端算好一份 `gen_params` 随任务下发，前端只渲染。
2. **白名单语义，不是「抄出来」**。LoRA 取值必须过「这个模式的工作流真的会读这个字段吗」+「这个值是真实存在的 LoRA 吗」**两道**判定。
3. **缺失就是缺失**。`gen_params` 里缺失的字段是空串 → 前端渲染成「—」，**绝不拿别的字段顶替**。
4. **不臆造**。判定为非法时**不编造**一个 LoRA 名 —— 用户要看到的是「无」。

### 3.2 后端 · 展示端白名单（`h3studio/job_meta.py`）

新增**单一判定入口**：

```python
def is_real_lora_key(value: str) -> str:
    """给一个字符串，判断它是不是**真实存在**的 LoRA 标识符。"""
    # 1) 长度上限（LoRA key 不可能是几百字的自然语言）
    # 2) 不含空白（提示词必有换行/空格）
    # 3) 在真实清单里：workflows.LORAS + video_models.VIDEO_ACCEL_LORA_COMBOS
    #                  + video_models.VIDEO_ACCEL_LORAS + loras.LORA_CATALOG
```

新增**按模式取值的唯一入口**：

```python
def resolve_job_lora(mode: str, params: dict) -> dict:
    """算出「这个任务真实用到的 LoRA」——**唯一入口**。

    1. 图像模式：读 params["loras"]（效果 LoRA 数组）——
       **不读** params["lora"]（旧前端无条件写的遗留字段，
       图像工作流根本不读它）。
    2. 音乐模式：没有 LoRA 概念 -> 全空。
    3. 视频新面板（params 有 model_key）：读 params["accel_loras"]
       + params["fixed_accel_lora"]（结构化字段，key 来自服务端清单）。
    4. 视频旧路径：读 params["lora"]，但值必须过 is_real_lora_key 白名单；
       "none" = 明确不用；非法值 = 视为没有；
       **没记录 lora** -> 工作流默认挂 ckpt850（workflows.py:344
       `lora = params.get("lora", "ckpt850")` 且 workflows.py:371-374
       确实会挂上）-> 显示 ckpt850。
    """
```

`_legacy_video_summary` 的取值也改为过白名单（非法值 → `lora_label` 留空，不编造）。

> **踩坑记录（已修）**：第一版 `resolve_job_lora` 对「没记录 lora 的老视频任务」返回「无」，
> 这是**错的** —— `workflows._h3_video_workflow:344` 的默认值是 `ckpt850` 且确实会挂上。
> 是 `tests/test_media_card_detail.py::test_legacy_video_without_lora_field_uses_workflow_default`
> 这条断言抓出来的。

### 3.4 前端兜底（`web/app.js`）

服务端已经判过了，但**老服务端**不会下发 `gen_params` —— 那时前端要自己兜底。判据与服务端同构，但**按来源区分**（这一点很重要，见 §7 踩坑）：

```javascript
const structured = Array.isArray(p.accel_loras)
  && p.accel_loras.some(item => item && item.enabled !== false && item.key);
if (info.lora_label) {
  if (!isVideo || structured || isLoraKeyLike(info.lora_label)) {
    parts.push(info.lora_strength != null
      ? `${info.lora_label} ×${Number(info.lora_strength).toFixed(2)}`
      : info.lora_label);

}
```

`isLoraKeyLike` = 「只允许 ASCII 标识符字符」（`/^[A-Za-z0-9_.\/-]+$/`）。

## 4. C2 / C3 / C4 / C5 实现

### 4.1 C2 —— 卡片补齐生成参数

**服务端**新增 `h3studio/job_meta.py:gen_params(mode, params, model_info, resolution_info)`，返回固定形状：

```python
{"model", "steps", "scheduler", "sampler", "shift", "cfg",
 "seed", "size", "duration", "lora", "attention", "workflow", "prompt"}
```

规则：
- 缺失 → 空串（前端显示「—」）；
- shift：视频读 `shift_video` + `shift_audio`（显示成「视频 12 · 音频 3」），图像读 `shift` —— **不互相顶替**；
- 时长：音乐读 `max_duration`，其余读 `duration`；
- 尺寸：**优先用 `resolution_info.width/height`**（服务端已按「产物实际像素优先」算好，与卡片显示口径一致），没有才回落 `params.width/height`；
- seed：没指定 → 「随机」（真实语义，不是缺失）；
- lora：走 `resolve_job_lora`，没有 → **「无」**。

**服务端** `server.py:row_to_job` 下发 `"gen_params": job_meta.gen_params(...)`。

**前端** `web/app.js:genParamRowsHtml(job)` 渲染成 `.job-meta .gen-params` 分组（8 行：模型 / LoRA / 采样器 / 调度器 / 步数 / 尺寸 / 时长 / 种子），缺失走 `paramOrDash()` → 「—」。

### 4.2 C3 —— 生成参数详情模态框

**HTML**（`web/index.html`）：独立 `#detailModal`（不复用 `#promptModal` —— 后者只有一个 textarea，详情要分区展示）。

**JS**（`web/app.js`）：
- `openDetailModal(job)` / `closeDetailModal()` / `isDetailModalOpen()`；
- 13 行参数：模型 / 步数 / 调度器 / 采样器 / shift / CFG / LoRA / 尺寸 / 时长 / 种子 / 注意力机制 / 工作流名 / 创建时间；
- 完整提示词用 `<pre>`（不是截断的 80 字）。

**四种关闭方式**（全部实测通过）：
1. × 按钮 `#detailModalClose`
2. 底部「关闭」按钮
3. `Esc`
4. 点遮罩（点到 `.prompt-modal` 本身才算，点对话框内部不算）

**与既有按钮互不冲突**：卡片的「详情」按钮 `event.stopPropagation()`；卡片的点击处理器排除
`button, a, .job-preview, .prompt-row, .job-batches, .job-batch, .cancel-btn, input, select, textarea`。

**定时刷新不打断**：模态框内容在**打开时快照**一次，之后 2 秒一次的 `refreshJobs` 轮询不会改写它（实测等 7 秒 ≥3 个轮询周期，内容逐字不变、模态框仍开着）。

**`body.modal-open` 统一维护**（`syncModalOpenClass()`）：页面上有多个模态框，关掉一个不能把另一个的滚动锁也解掉。

### 4.3 C4 —— 复用参数复用完整参数

- `reuseConfigFromJob()` 补齐 `cfg` / `seed` / `use_sigma_shift`（原来漏了 CFG 与种子，复现不出同一个结果）；
- 复用后**按「产物实际像素优先」**回填宽高（与卡片显示口径一致），并由宽高反查 `sizePresetKey`（唯一真源是服务端下发的 `size_presets` 清单）。

### 4.4 C5 —— 三档视口

`web/style.css` 新增 `.detail-dialog` / `.detail-body` / `.detail-kv` / `.detail-prompt` 规则：
- 宽度 `min(720px, 92vw)`；窄屏 `94vw` + `max-height: 88vh`；
- 中间内容区 `flex: 1; min-height: 0; overflow-y: auto`（**头尾固定、中间滚动** —— 不能给整个对话框加 `overflow:auto`，否则标题栏会跟着滚走）；
- 提示词 `white-space: pre-wrap; word-break: break-word; overflow-wrap: anywhere`；
- 参数表两列 → 窄屏一列。

### 过程中踩到并修掉的坑

1. **CRLF 行尾**：本仓库 `server.py` / `web/index.html` / `web/app.js` / `web/style.css` 的
   `.gitattributes` 标了 `-text`（必须 CRLF blob）。用 Python 脚本改文件时行尾被悄悄换成 LF，
   `tests/test_enhance_architecture_fixes.py::test_worktree_bytes_are_crlf` 抓到
   （`web/app.js 工作区有 5370 个裸 LF`）。已把四个文件**字节级**还原成 CRLF，
   `git diff --stat` 从全文件重写变回 954 insertions / 33 deletions 的正常 diff。
2. **前端白名单误杀真 LoRA**：第一版 `isLoraKeyLike` 用「不含空格」判，
   把真实显示名 `DMAD 4 步（critic 版）`（带空格和全角括号）也判成不是 LoRA。
   改成「只允许 ASCII 标识符字符」+「按来源区分（结构化字段 / 遗留字段）」。
3. **「没有 LoRA」与「没记录 LoRA」不是一回事**：老视频任务没记 `params.lora` 时，
   工作流默认挂 `ckpt850`（`workflows.py:344`）且**确实挂上**。第一版返回「无」是错的，
   被新增断言抓出后修正。
4. **模板嵌套层级**：改卡片模板时把两层 `${...}` 合并成一层，`node --check` 报
   `Missing } in template expression`。已修正并用 `node --check` 作为每次改动的门禁。
