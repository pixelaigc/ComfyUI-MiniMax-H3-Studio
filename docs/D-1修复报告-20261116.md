## 1. 根因

`job_meta.summarize()` 的摘要分派：

```
job_meta.py:1131   if mode == "t2v" and params.get("model_key"):  -> _t2v_summary(params)   ✅ 读 model_key
job_meta.py:1133   elif mode in ("t2v","flf","r2v","longfilm"):  -> _legacy_video_summary()  ❌ 读旧 key
```

`_legacy_video_summary()` 原先只读**旧 key** `params["model"]`（语义是 `"standard"` / `"lora"`）：

```python
job_meta.py:830   model = str(params.get("model") or "").strip()
```

而 flf / r2v 的**工作流**读的是 `params["model_key"]`：

```
h3_video_modes.py:445   unet_name = _vm.model_for_mode("flf", params.get("model_key"))["unet"]
h3_video_modes.py:559   unet_name = _vm.model_for_mode("r2v", params.get("model_key"))["unet"]
```

于是：`params["model"]` 取不到 -> 落 `_legacy_video_summary` 的默认分支 ->
显示 `minimax_h3_fl2va_pruned_int8_convrot.safetensors`（剪枝 int8 默认档），
而工作流**实际跑**的是用户选的 `minimax_h3_fl2va_int8_convrot.safetensors`。

线上落库实测（job `36cc7102d6e1`）：`model_key='fl2va_int8'`、`model=None`、
`artifact_model_file='minimax_h3_fl2va_int8_convrot.safetensors'` —— 复现条件齐备。

**不影响出片**（工作流真实生效底模/LoRA 均正确、产物正确）；影响**可见性**：
用户看到「剪枝 int8（默认档）」实跑完整 int8，与「前端选什么就加载什么」承诺冲突，
且误导显存/画质判断（完整 int8 34.0 GB vs 剪枝 int8 20.9 GB，差约 12 GB）。

LoRA 显示早有 worker `artifact_loras` 回写兜底，**底模显示没有** —— 这正是缺口。

## 2. 改了什么

**唯一改动文件：`h3studio/job_meta.py`（+54 / -1）**

### 2.1 `model_key` 优先（验收方建议 ①）

`h3studio/job_meta.py:830-861`（`_legacy_video_summary` 内）：

```python
model_key_param = str(params.get("model_key") or "").strip()
model = str(params.get("model") or "").strip()

video_model_meta = vmodels.VIDEO_MODELS.get(model_key_param) or {}
resolved_by_model_key = bool(video_model_meta)
if resolved_by_model_key:
    out["model_key"]  = model_key_param
    out["model_label"]= _video_model_label(model_key_param)
    out["model_unet"] = str(video_model_meta.get("unet") or "")
```

命中本机底模清单即**直接决定** `model_key` / `model_label` / `model_unet`，
不再走旧 key 分支，也**不**回落默认档。
（实现用 `resolved_by_model_key` 标志位而非改写 `model` 变量 —— 避免误落 `else` 默认分支。）

### 2.2 产物级兜底（验收方建议 ②）

`h3studio/job_meta.py:855-879`：没有 `model_key` 时，用 worker 从**构建好的 workflow**
反解回的 `params["artifact_model_file"]`（实际跑起来的权重）反查回底模 key：

```python
artifact_unet = str(params.get("artifact_model_file") or "").strip()
for key, meta in (vmodels.VIDEO_MODELS or {}).items():
    if str(meta.get("unet") or "") == artifact_unet:
        out["model_key"]=key; out["model_label"]=_video_model_label(key)
        out["model_unet"]=artifact_unet; resolved_by_model_key=True; break
else:
    out["model_unet"] = artifact_unet   # 权重不在本机清单 -> 如实显示文件名，不编造 key
```

本机 7 个底模的 `unet` 字段**两两不重复**（已实测枚举），反查唯一、无歧义。
`artifact_model_file` 由 `artifact_meta.apply_to_params()` 既有逻辑写入
（`artifact_meta.py:342`，`setdefault` 语义，不覆盖已有值）—— **无需改 artifact_meta.py**。

### 2.3 不回归保证

- 历史遗留任务（只有旧 key `model="standard"` / `"lora"`）行为**完全不变**；
- 既无 `model_key` 也无 `model` 的老任务仍显示默认档（不回归）；
- `t2v` 路径走 `_t2v_summary()`，**未触碰**；
- `ckpt850` 兜底分支（`job_meta.py:902` 附近）**未改动** —— 验收方提示的
  「该分支在新面板任务上不可达、仅对历史遗留任务生效」经复核**属实**，
  但属老语义且**不在 D-1 范围**，本轮**不改**（见 §6 未完成项）。
