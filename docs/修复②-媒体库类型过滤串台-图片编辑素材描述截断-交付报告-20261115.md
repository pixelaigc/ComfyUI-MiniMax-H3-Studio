## 1. 缺陷1：媒体库类型过滤串台

### 1.1 现象（用户实测）

1. 任意模型文生图点「生成」→ 媒体库「进行中」显示任务卡（正常）
2. 生成完成 → 「进行中」卡片消失，点「全部/已完成」能看到完成的媒体卡（正常）
3. **点左侧「minimax-h3 长片拼接」→ 右侧媒体库只显示视频素材**，图片/音频全部不显示
4. 即使「项目标签=全部」「生成类型=全部类型」也一样只有视频
5. **把「生成类型」改成刚才执行过的类型（如文生图）→ 该类别反而显示为空**
6. URL 变成 `http://192.168.3.78:8190/#/agent/50269d359dfa4106`（用户并未访问过 agent）

### 1.2 根因（现场代码 + 线上实测抓包）

**根因 A（直接原因）—— `web/app.js::refreshJobs()` 给共享媒体库强加 `media=video`**

线上修复前实测抓到的请求（`evidence-labc/fix2/probe_before.py` 输出）：

```
REQS: [".../api/jobs?status=all&page=1&page_size=12",
       ".../api/jobs?status=done&page=1&page_size=12&media=video",   <-- 点长片拼接后
       ".../api/jobs?status=done&page=1&page_size=12&media=video"]
STATE1_STITCH: 12 cards, kinds 全部 video（0 image）
```

对应源码（修复前 `web/app.js`）：

```js
if (state.page === "stitch" && state.stitchMediaOverride) {
  query.set("media", state.stitchMediaOverride);
}
```

`web/app.js::showStitch()` 里 `state.stitchMediaOverride = "video"`。

**为什么症状 4 和症状 5 是同一个根因**：
- 症状 4：媒体库被强制 `media=video` → 图片/音频不显示；
- 症状 5：`media=video` 与 `gen_type=t2i` **互斥**（SQL 里 `mode IN (video…) AND mode IN (t2i)`）→ 选中文生图反而**一条都查不到**。

线上实测验证互斥性：

```
status=done&gen_type=t2i&media=video   -> 0      <-- 用户报的「选中某类型却为空」
status=done&gen_type=t2i                -> 71
status=done&media=video                 -> 235
```

**根因 B —— `web/agent.js::show()` 写 `window.state.page` 是死代码**

```js
if (window.state) window.state.page = "agent";
```

`app.js` 里的 `state` 是**模块级 const**（`web/app.js:121 const state = {...}`），
**从未挂到 window 上** —— 全仓 `grep "window.state ="` 命中 **0 处**。
于是这行永远不执行，`app.js` 的 `state.page` 一直停留在上一个面板
（点过长片拼接就是 `"stitch"`）。

**它怎么污染媒体库**：Agent 页把媒体库整个藏起来了（`#jobsArea` 加 `page-hidden`），
但 `state.page` 仍是 `"stitch"` → **后台 2 秒轮询**仍按「长片拼接页」在拉数据
（`status=done&media=video`），用户回到「生成」页看到的就是被窄化过的结果。

**根因 C —— `web/agent_sessions.js::syncRoute()` 无条件写 URL**

`saveCurrentId()` → `syncRoute()` 是无条件调用，而 `saveCurrentId()` 在
**页面加载时的会话恢复**里也会走 → **用户从没点过 Agent**，只是打开工作台，
URL 就被写成 `#/agent/<某个会话id>`。这正是用户报的症状 6。

### 1.3 修复点

| 文件:行 | 修复 |
|---|---|
| `web/app.js:5899-5922` | 删除 `refreshJobs()` 里按面板叠加 `media` 的分支 —— 媒体库的 query **只**反映用户自己的筛选 |
| `web/app.js:6488` | `showStitch()` 里 `state.stitchMediaOverride = ""`（不再强加 video） |
| `web/app.js:6163-6246` | **新增** `collectStitchCandidates()` + `renderStitchCandidatePool()` —— 长片拼接的「只收视频片段」改由它**自己**的候选池实现（数据源复用 `window.JOB_CACHE`，零额外请求） |
| `web/index.html:893-904` | **新增** 长片拼接面板自己的「视频候选（当前页）」区域 |
| `web/style.css:253-282` | 候选池样式 |
| `web/app.js:6853-6879` | **新增** `window.H3Studio.notifyPageChange(page)` 窄接口 —— 别的模块说「我切到哪一页」，由 app.js 自己维护 `state.page`（单一真源） |
| `web/agent.js:2225-2247` | 改用 `notifyPageChange("agent")`，不再依赖不存在的 `window.state` |
| `web/agent_sessions.js:72-100` | `syncRoute()` 增加 `agentVisible` 判断 —— Agent 页不可见时不写 URL |

**设计原则**：媒体库是**所有面板共享**的列表，必须只反映**用户自己**的筛选条件；
面板的局部视图（长片拼接只要视频片段）由面板**自己**的区域实现，不泄漏到全局。

## 2. 缺陷2：图片编辑素材描述被截断只传第一行

### 2.1 现象

H3-IMAGE 图片编辑 与 Qwen-Image 2.1 图片编辑面板，从素材库加一张图后，
`<image1>` 输入框里只显示「基于您提供的图片素材，以下是详尽的中文内容描述：」这一行首句。

### 2.2 根因

**根因 A（后端，直接原因）—— `h3studio/ref_api.py::_condense()`**

```python
def _condense(text: str, limit: int = 80) -> str:
    """把长描述压成一行短句（占位描述用）。..."""
    for chunk in text.replace("【", "\n【").split("\n"):
        chunk = chunk.strip()
        if len(chunk) > 6:
            text = chunk
            break          # <-- 只取第一个有内容的小节
    text = text.replace("【", "").replace("】", " ")
    text = " ".join(text.split())
    if len(text) > limit:  # <-- 再截断到 80 字
        text = text[:limit].rstrip() + "…"
    return text
```

`_describe()` 走的就是它。素材库的分析文本是**多小节**长描述
（实测 184 条，最长 5250 字，平均 449 字）→ 参考图描述只剩首行首句。

线上实测（修复前）：

```
curl 'http://127.0.0.1:8190/api/refs/assets' | ...
"description": "基于您提供的图片素材，以下是详尽的中文内容描述："    <-- 只有这一行
```

DB 里的**原文**是 1368 字 / 31 小节（`asset_33974c66468e`）：

```
基于您提供的图片素材，以下是详尽的中文内容描述：

【主体人物】
画面中心为一名年轻女性动漫角色...
【服装与配饰】
*   **上衣**：身穿一件白色的立领衬衫...
...
【其他值得注意的细节】
*   人物的紫色瞳孔中有独特的十字星芒设计。
```

**根因 B（更严重，用户没报但同源）—— H3-Image 那条路**根本没注入过描述**

- `server.py` 的 `i2i_h3image` 分支只做校验，然后把 `params["ref_images"] = refs`（带 description）交出去；
- 但 worker 跑的时候（`server.py::_run` 的 `i2i_h3image` 分支）调 `_upload_asset_refs(...)`，
  **用上传后的文件名列表覆盖** `params["ref_images"]` → description 就此丢失；
- `h3image.build_h3_image_workflow` 只把 `params["prompt"]` 送进 `MiniMaxH3ImageConditioning`
  → 模型**从来没看到**素材描述。

**根因 C —— Qwen 路径「用户自己写了 `<imageN>`」时整段丢掉描述**

```python
if parse_placeholders(prompt):
    return prompt      # <-- 描述整段没了
```

用户自己写 `<image1> 把雪豹放进这张图` → 模型知道有图1，但**不知道图1是什么**。

**根因 D（显示侧）—— `web/qwen-refs.js` 文本框写死 `rows="2"`**

后端修好后，前端仍只显示 2 行 → 用户看到的现象与「描述被截断」一模一样。

### 2.3 修复点

| 文件:行 | 修复 |
|---|---|
| `h3studio/ref_api.py:42-88` | `_describe()` 改用 `_normalize()`：**完整保留**分析文本（只去 `\r`、压连续空行，不取首节、不截断） |
| `h3studio/ref_api.py:90-135` | **删除** `_condense()`（留着它 = 缺陷随时被重新引入）；新增 `_normalize()` + `DESCRIPTION_MAX_CHARS = 40000`（实测素材最长 5250 字，等于不设限，仅防异常膨胀；超限时**明确标注**截掉了多少字，不静默） |
