## 二、开关为什么不见了（实测根因，不是推测）

开关 DOM：`#vidTwopassAllowContinuationRow`（容器）/ `#vidTwopassAllowContinuation`（复选框）

可见性判定在 `web/video-panel.js::renderTwopass()`：

```js
const hasContinuation = !!(window.Continuation && window.Continuation.state
    && window.Continuation.state().current
    && window.Continuation.state().current.continuation);
allowRow.hidden = !hasContinuation || !videoState.twopass.enabled;
```

而 `web/continuation.js::start()` 的执行顺序：

```
applyToPanel(ctx)   -> VIDEO_PANEL.render() -> renderTwopass()
                       ↑ **此刻 current 还是旧的（null）**
                         => hasContinuation === false => 开关被藏
current = ctx       -> 现在接续上下文才真正就绪
renderPanel()       -> 只渲染「接续上下文」只读区，**不碰**视频面板
applyAssetRefs(...) -> **有**素材时末尾调 renderModeKeepSlots() -> 重渲染 -> 开关显形
                       **无**素材时**早退**，**不重渲染** => 开关永远藏着
```

⇒ **开关的可见性依赖「有没有素材」这个副作用。**

### 12 组矩阵实测（3 模式 × 有/无素材 × 二采开/关）

修复前：

| | refs=0 | refs=1 |
|---|---|---|
| t2v | tp=0 hidden / tp=1 **hidden** | tp=0 hidden / tp=1 **hidden** |
| flf | tp=0 hidden / tp=1 **hidden** ← 缺陷 | tp=0 hidden / tp=1 显形 |
| r2v | tp=0 hidden / tp=1 **hidden** ← 缺陷 | tp=0 hidden / tp=1 显形 |

修复后（全部 12 组符合预期）：

「有二采开关」≡「有二采上下文 **且** 二采已开」，与模式、与有无素材**无关**。

### 为什么用户看到的现象与「没传 continuation」一模一样

两者都是「点了接续，接续上下文区域显示了，但二采区块里那个开关不见」——
用户分辨不出根因。所以修**可见性**这条真正断的链路是对的。

## 三、改了什么

分支：`local/feature/cont-params-continuation`（worktree `/root/projects/h3studio-cont-param`）
基于 `local/maintainer` @ `7670f6c`

### `web/continuation.js`（+70 行）

新增 `rerenderVideoPanel()`：在**接续上下文就绪之后**显式重渲染一次视频面板。

三处调用：

| 位置 | 作用 |
|---|---|
| `start()` | 接续上下文就绪后（素材回填之后）→ 开关显形 |
| `clear()` | 清除上下文后 → 开关重新隐藏（否则留在界面上） |
| `clearForReuse()` | 「复用参数」清掉上下文后 → 同上 |

**为什么不用 `renderModeKeepSlots()`**：它会重渲染整个左侧配置区（含素材槽位 DOM），
而这里只需要视频面板的几个区块跟着接续上下文更新。`VIDEO_PANEL.render()` 粒度更小、不碰槽位。

**为什么放在 `applyAssetRefs` 之后**：素材回填会调 `renderModeKeepSlots()`（它自己会重渲染），
但那**只在有素材时**发生。放在素材回填**之后**统一补一次，两种情况都覆盖，且不与素材回填那次渲染打架。

### `web/index.html`（+1 行）

升 `continuation.js` 的 `?v=` 缓存版本号：`cr20261118a` → `contsw20261119a`。

**这一步不能省**：`/static/*` 没有 `Cache-Control`，浏览器按启发式新鲜度缓存。
continuation.js 内容变了而 `?v=` 不变 ⇒ 老用户浏览器拿到的仍是旧文件 ⇒ **修复等于没上线**。
（本仓惯例：`0ac8ecf` / `45aab0e` / `56152fd` / `e1cf598` 都是同一件事。
本轮改的是 continuation.js，不是 app.js，所以上一轮 bump 的 `app.js?v=cont20261119a` 不用动。）

行尾：index.html 是 CRLF（`.gitattributes` 的 `-text` 规则）—— 用行级精确替换保持字节原样
（1 行改动，CRLF 计数 1614 不变）。
