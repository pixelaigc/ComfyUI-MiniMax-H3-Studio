## 1. 根因

`job_meta.summarize()` 的摘要分派：`t2v` 走 `_t2v_summary()`（用 `resolve_accel_lora_slot()`）✅；
`flf` / `r2v` 走 `_legacy_video_summary()`，其 **LoRA 分支只读旧 key `params["lora"]`**：

```python
job_meta.py:911   if lora == "none": ...
job_meta.py:914   elif lora:   # <- 只认旧 key
...
job_meta.py:951   else:
                       # 【没有记录 lora】-> 工作流默认 ckpt850
                       out["lora_label"] = "ckpt850"     # <- 写死
```

而 flf / r2v 的**工作流**读的是新面板字段：

```
h3_video_modes.py:445  unet_name = _vm.model_for_mode("flf", params.get("model_key"))["unet"]
video_workflow.py:85   key, strength = vmodels.resolve_accel_lora_slot(params)
                         # <- 读 accel_lora / accel_loras / fixed_accel_lora / lora
```

新面板**永远**写 `accel_lora` / `accel_loras` / `fixed_accel_lora`
（`server.py:normalize_t2v_params` 归一层实测：`out["accel_lora"]=...` / `out["accel_loras"]=[...]`
/ `out["fixed_accel_lora"]=...` 三者恒写），**不写**旧 key `params["lora"]`。

⇒ `_legacy_video_summary` 的 LoRA 分支恒落「没记录 lora」分支 ⇒ **恒显示写死的 ckpt850**。

`params["lora"]` 为空的两个窗口：
- **queued 窗口**：worker 尚未回写 `artifact_loras`（`params["artifact_loras"] = null`）
  → 外层 `_artifact_lora_overlay()` 不生效 → 框内显示 `ckpt850`；
- **failed 任务**：worker 失败 → **永不**回写 `artifact_loras` → **永不自愈**。

线上现场（修复前）：
- job `95fefee8803e`（flf, **failed**）：用户选 `lightx2v_4step_768p` → 框内 `ckpt850 ×1.00`
- job `9591a1d8c7c8`（flf, queued）：用户选 `better_motion` → 框内 `ckpt850`（同卡 `gen_params.lora` 正确）

**不影响**底模字段（D-1 已修复）、**不影响**工作流实际挂载；
但直接违反 c1「不再固定为 Turbo 4 步 ckpt850」与「前端选什么就加载什么」的承诺。

## 2. 改了什么

**唯一改动文件：`h3studio/job_meta.py`（+101 / -6）**，全部在 `_legacy_video_summary()` 的 LoRA 分支内。

### 2.1 改用统一的槽位换算（验收方建议 ①的等价实现）

`h3studio/job_meta.py:951-1040`（原「没有记录 lora -> 写死 ckpt850」分支）：

```python
has_slot_evidence = (
    "accel_lora" in params
    or "accel_loras" in params
    or "fixed_accel_lora" in params
)
slot_key, slot_strength = vmodels.resolve_accel_lora_slot(
    params, include_fixed_fallback=True)
if slot_key and (slot_key != vmodels.VIDEO_FIXED_ACCEL_LORA_DEFAULT
                 or has_slot_evidence):
    # 有真实槽位证据 -> 显示用户所选那枚
    out["lora_label"] = _accel_lora_display(slot_key)
    out["lora_name"]  = str(meta.get("name") or "")
    out["lora_key"]   = slot_key
    out["lora_strength"] = float(slot_strength)
    out["accel_lora_loader"] = vmodels.detect_accel_lora_loader(meta["name"])
else:
    if has_slot_evidence and not slot_key:
        # 明确「不挂加速 LoRA」-> 什么都不显示，不回落 ckpt850
        out["lora_label"] = ""; out["lora_key"] = ""; out["lora_strength"] = None
    else:
        # 什么都没记的历史老任务 -> 工作流确实挂默认 ckpt850，如实显示
        out["lora_label"] = "ckpt850"
        out["lora_name"]  = str(wf.LORAS.get("ckpt850") or "")
        out["lora_key"]   = "ckpt850"
        out["lora_strength"] = 1.0
```

### 2.2 为什么 `include_fixed_fallback=True`（与验收方建议的差异，已实测论证）

验收方建议用 `resolve_accel_lora_slot(params, include_fixed_fallback=False)`。
**实测发现该参数为 False 时，旧 key `params["lora"]` 根本不会被返回**：

```
resolve_accel_lora_slot  实测（include_fixed=False / True）
  accel_loras=[lightx2v]  -> ('lightx2v_4step_768p', 1.0) / ('lightx2v_4step_768p', 1.0)
  accel_lora="" (不挂)    -> ('', 1.0)                  / ('', 1.0)
  lora="ckpt850" (旧 key) -> ('', 1.0)                  / ('ckpt850', 1.0)   <- False 丢失旧 key
  lora="none"             -> ('', 1.0)                  / ('', 1.0)
  完全没有任何字段         -> ('', 1.0)                  / ('ckpt850', 1.0)
```

若直接采用建议的 False：历史老任务（只有旧 key `lora`）会**丢掉 LoRA 显示** → 回归。
故采用 **True**，并用 `has_slot_evidence` 把「用户/面板写过槽位字段」与「什么都没写」区分开 ——
这正是 `include_fixed_fallback=False` 原本想表达的语义，但 False 会连带丢掉旧 key，故在调用侧显式判定。

### 2.3 三种情况的显示口径（均如实，不谎报）

| params 形态 | 工作流实际挂载 | 卡片 LoRA 行 |
|---|---|---|
| 新面板选了某枚（`accel_lora`/`accel_loras`） | 那枚 | **那枚**（友好显示名 + 真实权重名 + loader） |
| 明确不挂（`accel_lora=""` / `accel_loras=[]`） | 不挂 | **不显示任何 LoRA**（不回落 ckpt850） |
| 什么都没记（历史老任务） | 默认 ckpt850 | `ckpt850`（**原样**，老显示口径） |

### 2.4 未回归保证

- 旧 key `params["lora"]`（ckpt850 / v4step600）仍按旧 key 显示；
- 脏值（提示词冒充 LoRA）仍被白名单闸门挡掉（`is_real_lora_key`）；
- 既有契约 `test_missing_lora_falls_back_to_workflow_default`
  断言的**原样 `"ckpt850"`** 保持不变（**本次修复过程中一度破坏该契约，已修正**——
  首版实现对「无字段」情形也走了友好显示名 `"Turbo 4 步 · ckpt850"`）；
- `t2v` 路径（`_t2v_summary`）**未触碰**。
