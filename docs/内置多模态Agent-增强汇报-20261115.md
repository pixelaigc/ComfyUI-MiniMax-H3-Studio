## 4. 增强方向 4 —— 性能与稳定性

### 4.1 `/api/image-loras` 性能

本轮线上实测（2026-11-15，`curl -w '%{time_total} %{size_download}'`）：

| base | 耗时 | 响应体 |
|---|---|---|
| Z-Image | 2.078778 s | 6,129,236 bytes |
| Qwen-Image 2.1 | 0.097016 s | 124,845 bytes |
| MOSS-Image | 1.298389 s | 3,801,578 bytes |

轻量判定生效（`127603a`）：结构兼容性只读 safetensors **头部**，权重级分析（相对扰动 / ctx 阻尼）改为按需触发。
> 早期《总汇报》记「0.90s / 3.8 MB」；本轮实测响应体已大于该数（LoRA 目录期间增补），**以本轮实测为准**。

### 4.2 LoRA 同名 key 冲突台账

运行时读 `loras.LORA_CATALOG_CONFLICTS` = **18 个冲突 key / 36 条目**，每条含 source / plan_id / kept，且每个 key 恰好一条 `kept=True`（`127603a`）。

### 4.3 前端轮询终止条件

`JOB_POLL_MAX_MS` 上限（`17a2021`），避免任务卡永久「运行中」。

### 4.4 SSE 取消与硬超时

`web/agent.js` 含 `AbortController` + `controller.abort()`；`SSE_MAX_MS` 硬超时。验收实测「取消后文案=已停止生成、`abortedMidStream=true`（三档）」。

### 4.5 MOSS 批量出图 steps 被写死为 5 —— 根因与实测

根因（`server.py` `_run_batches()`）：批次分支用 `params.get("mode") or "t2i"`，而 DB 的 params JSON **从来没有 mode 键** → MOSS 批量任务落到批次分支时 mode 变 `"t2i"` → 走 Z-Image t2i 工作流 → 用户设的 steps=100/cfg=4.3/shift=5 全部被忽略。

修复后从 ComfyUI `/history` 原始 KSampler 节点取证：5 张批次每张 `steps=100, cfg=4.3, sampler=euler, scheduler=sgm_uniform`，**seed 互不相同、其余参数一致**（`683e6fb`）。

### 4.6 「停止」按钮取消路径 ReferenceError

`567c304` / `f1578f3` / `37a67a3` 修复，变异验证：28 passed → 回退 → **2 failed** ✅ → 恢复 28 passed。

  LORA_CATALOG 里的 `base_verdict: "原生"` 更让它看起来像「原生就能直接挂」。
