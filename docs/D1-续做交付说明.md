## 1. 复核：两处缺陷的实际触发路径

动手前先把「转述」变成「实测复现」。复现脚本（临时）：

```python
hist = {"status": "execution_error", "outputs": None}
status_info = hist.get("status") or {}
status_info.get("status_str")
# ❌ AttributeError: 'str' object has no attribute 'get'
```

```
$ /home/ubuntu/comfyui/venv/bin/python - <<'PY'
...
status_info type: str 'execution_error'
❌ CRASH: AttributeError: 'str' object has no attribute 'get'
PY
```

**结论**：两处缺陷都**真实存在**，触发条件是 `history["status"]` 为字符串。

> ⚠ 与转述有一处**出入**：缺陷不在 `video_workflow.py`。
> `h3studio/video_workflow.py` **不解析** ComfyUI history（它只拼工作流）。
> 真正解析 history 的是 `server.py` 的 worker 轮询循环 +
> `h3studio/comfy_errors.py` 的提取函数。
> 本轮按**实际代码路径**修（修在真正出问题的地方），而不是按转述指的位置。

### 为什么这个 AttributeError 特别糟

它发生在**错误处理路径上** —— 本来要把 ComfyUI 的失败原因翻译成中文给用户，
结果自己先崩了。于是：

1. 真正的原因（例：拷贝桥禁止跨分辨率）**被彻底丢掉**；
2. 用户最终只看到一句 `'str' object has no attribute 'get'`；
3. 而且这句文本**对用户零信息量** —— 它是本项目的 bug，不是用户能修的东西。

## 2. 修复①：ComfyUI history 解析的类型免疫

### 2.1 三层纵深防御

| 层 | 位置 | 职责 |
|---|---|---|
| L1 | `comfy_errors.coerce_status_info(status_info)` | 非 dict（含 None/str/list）→ 一律归一成**空 dict** |
| L2 | `comfy_errors.status_is_error(status_info)` | 对类型免疫的错误判定 |
| L3 | `server._history_status(hist)` | **新抽出的**可测 helper，返回 `(status_info, is_error, malformed)` |

worker 的两处轮询循环（主任务 / 批次）都改调 `_history_status` ——
类型判断**只此一处**。

### 2.2 为什么要抽成 helper（而不是原地加个 `isinstance`）

这个判断原本**内联**在 worker 的轮询循环里。它一旦被改回旧写法，
只有「真跑一次 ComfyUI 并让它失败」才能发现 —— 而且是在**失败路径**上，
平时根本走不到。

抽成独立函数后：

* 单元测试可以直接喂各种畸形 history 并断言「不抛异常」；
* 变异验证可以精确地把这一行改回旧写法，确认测试**真的会红**。

### 2.3 关键语义：`status` 是 `None` ≠ 畸形

ComfyUI 在任务**还没跑完**时，history 里的 `status` 就是 `None`
（`execution.py` 的 `status_dict` 初值是 `None`，`task_done` 时才填成 dict）。
那是「**还在跑**」，不是「形状坏了」。

> ⚠️ 本轮**一开始**把 `None` 也当畸形 —— 这是**错的**：
> 会让所有「刚提交、还没跑完」的任务立刻失败。
> 写运行时取证脚本时场景 B 跑不出来（worker 一直轮询），顺着这条线查出来的。

本机实测（ComfyUI 0.37，5 条历史）：

```
0a410ff4-984 status_type=dict status_str='error'   outputs=0
4d33ceb3-50a status_type=dict status_str='success' outputs=1
4675292f-02c status_type=dict status_str='error'   outputs=0
cedd7cf7-52b status_type=dict status_str='success' outputs=1
69b8e00f-4bf status_type=dict status_str='error'   outputs=0
```

`status` **总是** dict。畸形只可能来自：中间代理/网关改写响应、未来 ComfyUI
改形状、测试构造的假数据。但「万一」也必须优雅降级 —— 不能挂死。

## 3. 修复②：前端不再展示原始 Python 异常文本

### 3.1 服务端（源头）

worker 兜底原本是：

```python
except Exception as e:
    conn.execute("UPDATE jobs SET ... error=? ...", (str(e)[:800], ...))
```

`str(e)` 把**原始异常文本**直接写进 `jobs.error`，前端原样显示。

改成走 `_user_facing_error(e)`：

| 输入 | 输出 |
|---|---|
| 已中文化的 `RuntimeError`（含中文） | **原样保留**（那是已经翻译过的原因） |
| 其它异常（`AttributeError` / `ValueError` / …） | 归类成可读中文，**原始文本只进服务端日志** |
| 空异常 | 通用文案 |

批次路径与 longfilm 路径**同步修**（三处 `str(e)[:800]` 全部替换）。

### 3.2 前端（兜底层）

新增 `friendlyError(text)`，识别 Python 异常文本的特征：

```javascript
const PY_EXCEPTION_PATTERNS = [
  /^[A-Z][A-Za-z_]*(Error|Exception|Interrupt|Warning)\b\s*[:：]/,  // ValueError: ...
  /'[^']+' object has no attribute/,                                 // 'str' object has no attribute 'get'
  /"[^"]+" object has no attribute/,
  /\bTraceback \(most recent call last\)/,
  /File "[^"]+", line \d+/,                                           // traceback 行
];
```

命中 → 换成可读中文；**不命中 → 原样展示**（正常的中文原因一个字都不改）。

前端这一层防的是：

* **修复前建的老任务** —— 库里存的本来就是原始文本；
* 任何**新引入的写入路径**漏掉服务端那一层。

两处错误展示点都改走 `friendlyError`：

```javascript
// web/app.js —— 任务卡片
preview = `<div class="progress-wrap"><div class="err-text">✕ ${friendlyError(job.error)}</div></div>`;
// web/app.js —— 批次缩略图
failed ? friendlyError(batch.error).slice(0, 60)
```

### 3.3 分类器实测（真实 node 执行 app.js 里的实现）

| 输入 | 输出 |
|---|---|
| `'str' object has no attribute 'get'` | → 替换成中文（原文不展示） |
| `ValueError: 拷贝桥禁止跨分辨率` | → 替换成中文 |
| `Traceback (most recent call last):` | → 替换成中文 |
| `  File "/root/server.py", line 118, in _run` | → 替换成中文 |
| `拷贝桥禁止跨分辨率：上段 768x448 ≠ 本段 1024x576` | **原样展示** |
| `生成已被中断（可能是 ComfyUI 侧取消了任务）。` | **原样展示** |
| `本机 ComfyUI 暂时无响应，接续节点状态未探全 —— 接续功能按可用处理。` | **原样展示** |
| `""` / `null` / `undefined` | → `生成失败` |

## 4. 自查发现并修掉的回归（本轮自己引入的）

### 4.1 现象

`01d927d` 提交后，`status` 是字符串时 `status_is_error` 返回 False
（没有 `status_str` 可读）→ worker 既没拿到 outputs（没成功）也没判定成 error
（不是失败）→ 轮询循环**没有任何退出条件** → **任务永远卡在「生成中」**。

这比原来的 AttributeError **更糟**：原来至少会失败，现在**挂死**
（占着队列、用户看到永远转圈）。

### 4.2 发现方式

写运行时取证脚本时，场景 B（`status` 是 `None`）跑不出来 —— worker 一直轮询。
顺着这条线查出来的。

### 4.3 修法

`_history_status` 增加第三个返回值 `malformed`：
`status` 存在但**不是 dict** → 标记为畸形 → worker **立即失败**并给出
`comfy_errors.MALFORMED_STATUS_REASON`（可读中文，说明是格式异常）。

`status` 是 `None` **不算畸形**（见 §2.3）。

### 4.4 教训

**「加了类型判断」不等于「修好了」。** 类型判断把崩溃换成了静默挂死 ——
从「报错」变成「不报错但不结束」，用户体感更差（永远转圈 vs 立刻失败）。
这类回归只有在**真跑一遍失败路径**时才会暴露。

## 7. 已知限制与未完成项

1. **`_history_status` 的 `malformed` 判定是「启发式」**：
   `status` 存在但不是 dict -> 畸形。理论上 ComfyUI 未来若把 `status` 改成
   别的结构（例如 list），会被判成畸形并快速失败 —— 这比挂死好，但仍是
   「快速失败」而非「正确解析」。本机 ComfyUI 0.37 实测 `status` 总是 dict。

2. **`status` 是 `None` 时的「还在跑」判定依赖 ComfyUI 的语义**：
   本轮按 `execution.py` 的 `status_dict` 初值为 `None` 来认定
   「还没跑完」。若 ComfyUI 改了语义（比如 `None` 表示「已失败但无详情」），
   worker 会继续轮询直到超时。

3. **前端分类器是启发式**（正则匹配）。极罕见的合法错误文案如果长得像
   Python 异常（例：`ValueError: 这个值不对`）会被替换成通用文案。
   代价可接受 —— 原文仍在服务端日志里。

4. **老任务的 `jobs.error` 仍是原始 Python 文本**（历史数据）。
   前端 `friendlyError` 会在**展示层**替换掉它，但**库里**的老记录没回填。
   要回填需要写一次性迁移脚本 —— 本轮**未做**（超出本次范围）。

5. **本轮未做**：未合并主线、未部署 8190、未重启线上服务 —— 按仓库纪律留给主线统一收口。

6. **全量回归**：`pytest tests/ -q` 的结果见 §8。
