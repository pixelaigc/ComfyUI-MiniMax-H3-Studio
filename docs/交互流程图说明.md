## 1. 这份图解决什么问题

「人机交互流程图」如果纯手写，一定会**和代码漂移**：加一个生成模式、换一个增强方式、
改一次素材槽位上限，图就过期了，而且没人会发现 —— 直到有人照着过期图做需求。

所以本套图的做法是：**骨架手写、节点派生**。

| 部分 | 谁维护 | 位置 |
|---|---|---|
| 流程**形状**（有哪些阶段、谁连谁） | 人工 | `scripts/templates/*.mmd` |
| 流程**节点内容**（模式名、工具名、路由、字段、动作） | **从代码自动读出** | `scripts/gen_flow.py` |
| 生成产物 | 脚本 | `docs/交互流程图-*.mmd` / `.svg` / `.png` |
| 与代码的对应证据 | 脚本 | `docs/交互流程图-派生清单.md` |

改代码 → 跑 `make flow` → 图立刻跟着变。这是本套图「未来修改内容后也能实时体现」的落点。

## 4. 主要用户路径清单

以下是本图覆盖的**全部主要用户路径**。每条都标了「在图里哪里看」和「代码/接口对应点」。

### 4.1 文生图

- **路径**：左侧导航「文生图」→ Z-IMAGE / Qwen-Image 2.1 / MOSS-Image / H3-Image → 图像面板 → 提示词 + 增强 → 点「生成」→ 生成库。
- **面板字段**：分辨率档位、输出尺寸、画面比例、生成批次、Z-Image 模型、调度器、负面提示词、SLG（MOSS 专属）、参考图、LoRA。
- **模式**：`t2i` / `t2i_qwen` / `t2i_moss` / `t2i_h3image`（`h3studio/gen_types.py`）。
- **图**：[创作链路](交互流程图-创作链路.mmd) ①②③④⑤。

### 4.2 图片编辑（Qwen 图片编辑 / H3-Image 图片编辑）

- **路径**：导航「图片编辑」→ 图像面板 → **参考图必须来自素材库**（点「从素材库添加」选 ≥1 张）→ 提示词里必须带 `<imageN>`（Qwen）/ `<Picture N>`（H3-Image）占位标记 → 生成。
- **上限**：Qwen ≤10 张；H3-Image 官方 16 张（`web/app.js` 按模型族取上限）。
- **占位校验**：提交前前端跑 `QwenRefs.validate()`，不过直接拦下（`web/app.js`）。
- **模式**：`i2i_qwen` / `i2i_h3image`；槽位 `ref_image`。
- **图**：[创作链路](交互流程图-创作链路.mmd) ①②⑤；[素材库](交互流程图-素材库.mmd) 素材→创作面板那条边。

### 4.3 h3 image 文生图（H3-Image）

- **路径**：同 4.1，入口是导航里的「H3-Image」。
- **规格**：6 步蒸馏、guidance 固定 1（**无 CFG pass → 无负面提示词**）、宽高 32 的倍数、参考图官方上限 16 张（`web/app.js` 顶部注释 + `h3studio/h3image.py`）。
- **模式**：`t2i_h3image` / `i2i_h3image`。

### 4.4 文生视频（MiniMax-H3，含效果 / 加速 LoRA、接续生成）

- **路径**：导航「视频 → 文生视频」（两级导航，类别→模型，清单由 `/api/video-categories` 下发）→ 文生视频面板 → 提示词 + 增强 → 点「生成」。
- **面板字段**：尺寸预设（H3 原生画布内）、输出尺寸、画面比例、MiniMax-H3 模型、**加速 LoRA（单选，按主模型适配过滤）**、**效果 LoRA（可多选，与加速 LoRA 并存）**、注意力机制、**二采（低分辨率一采 + 高分辨率二采）**、采样参数（步数 / CFG 固定 1 / shift 视频 / shift 音频 / 采样器 / 调度器）。
- **效果 LoRA 清单**：`GET /api/video-effect-loras`（独立于图像侧的 `/api/image-loras`，因为视频基座层结构不同）。
- **接续生成**：**只能**从生成库视频卡片点「⏭ 接续」→ `GET /api/jobs/{id}/continuation` → 回填接续上下文（**提示词不含在上下文里，由用户自己写下一段**）→ 再点生成。
  能否接续由服务端逐任务算（`continuation_service.build_continuation_context`），不可接续时明确给出中文原因，不静默失败。
  本机是否装了 Relay-Kit 节点由 `GET /api/continuation/state` 探测 —— **能力位由服务端下发**。
- **图**：[创作链路](交互流程图-创作链路.mmd) ②③④⑤（接续那条虚线回填边）。

### 4.5 首尾帧 / 参考生视频

- `flf`：首帧（必需）+ 尾帧（可选），槽位 `first_frame` / `last_frame`，各 ≤1。
- `r2v`：参考图（`ref_image` ≤10）/ 参考视频 / 参考音频，槽位由服务端按素材**真实类型**分派（`agent_schema.MODE_MEDIA_SLOTS`）。
- 两者走旧面板，但**采样参数区块**（采样器 / 调度器 / shift / CFG）与文生视频一致（`web/app.js` `renderLegacyVideoSampling`）。

### 4.6 长片拼接

- 路径：导航「视频 → 长片拼接」→ 从右侧生成库卡片点「＋ 拼接」或整卡拖拽 → 填标题 / 简介 → 片段 ≥2 → 「合成长片」→ `POST /api/longfilms` → ffmpeg concat 合成。
- 后端会校验每个片段文件仍然有效，失效直接 400。

### 4.7 音频 / 音乐生成

- **文生音乐 `t2a`**：音乐面板（YuE2 音乐模型 / 音频编码器 SheetSage2 / 音乐描述 / 结构化风格 Style Fields / 歌词 Lyrics / 谱面规划 ABC Planning / 输出格式 / 种子）。
- **参考生音乐 `a2a`**：额外需要**参考音频 1 段**（从素材库选），槽位 `ref_audio`。
- **音乐专用增强**：`POST /api/music-enhance`（与 `/api/enhance` 分开：前者是 YuE2 结构化风格 + 歌词）。
- **歌词留空 = 纯器乐**（面板明写）。

### 4.8 媒体库与生成库

- **生成库（媒体库）= `#jobsArea`**：状态标签（全部 / 进行中 / 已完成 / 长片 / 失败 / 已取消）+ **生成类型标签**（`GET /api/generation-types` 下发 12 种 + 兜底「其它生成」）+ 已完成筛选（搜索 / 作品类型 / 画面比例 / 作品时长）+ 每页条数。
- **素材库 = `#assetsPage`**：工具条（搜索 / 分类芯片 / 标签筛选 / 来源 / 排序）、上传（Web / 拖拽 / 带标签与备注）、素材卡片、详情抽屉、回收站（可恢复）、素材选择器。
- **双向联动**：生成库卡片右键「添加到素材库」→ `POST /api/assets/import/from-media`；素材库选择器 → 回填创作面板的参考图 / 参考音频 / 首尾帧。
- **图**：[素材库](交互流程图-素材库.mmd)（整张图就是这条链路）。

### 4.9 复用参数

- 生成库卡片点「复用参数」→ `reuseConfigFromJob()`（**纯函数**，`web/app.js`）→ 回填模式、模型、尺寸、比例、**LoRA 连强度与触发词**、**效果 LoRA**、采样参数（步数 / 采样器 / 调度器 / shift）。
- **口径与「详情」模态框一致**（同走 `web/job-meta.js` 的 `modelInfo()`），不会出现「详情显示一套、复用是另一套」。
- **图**：[创作链路](交互流程图-创作链路.mmd) ⑤ 里那条回填虚线。

### 4.10 队列生成

- 所有面板的「生成」→ `POST /api/jobs` → 落库 `status='queued'` → **单 Worker 按 `created_at` FIFO 取任务**（`server.py` `Worker._next_queued`）→ ComfyUI 执行 → `done` / `failed`。
- **队列面板**：任务区顶部，`GET /api/queue` 轮询，显示顺序 / 状态 / 计数；排队中的任务可直接「取消」（`POST /api/jobs/{id}/cancel`）。
- **状态实时推送**：`GET /api/status/stream`（SSE，1 秒一次，内容变化才推）。
- **连续提交不被拦**：提交后**不清空**参考图 / 参考帧 / 素材引用（队列化改造时改的，见 `web/app.js` 提交回调注释）。

### 4.11 内置 Agent 会话（新建交互 / 工具调用 / 音视频合并）

- **新建交互**：页头「☰」→ 抽屉「＋ 新建交互」；可搜索会话、切换会话、删除会话（`delete-session`）。
- **工具调用**：流式 SSE `POST /api/agent/chat/stream`，进度阶段文案来自服务端 `PROGRESS_STAGES` / `TOOL_STAGE_TEXT`。
- **音视频附件**：点「📎 媒体」上传 —— **图片 ≤9、音视频 ≤4，分开计数**（`web/agent.js` `MAX_ATTACHMENTS` / `MAX_MEDIA_ATTACHMENTS`）。
  **图片同步入库**（多模态分析 + 打标签，实测约 120~180 秒）；**音视频异步分析**（`analysis_jobs`），前端轮询 `GET /api/agent/media/{id}/status`。
  上传的音视频会**入库素材库**，之后可作为参考图 / 参考音频 / 参考视频被 `r2v` 消费 —— 这就是「音视频合并」的真实落点：
  **附件 → 素材库 → 参考槽位**，而不是把音频和视频合成一个文件。
- **工具能力位**由服务端下发（`agent_schema.MODE_SLOTS` / `mode_slot_plan`），前端不再硬编码「哪些模式建不了」。
- **图**：[内置 Agent](交互流程图-内置Agent.mmd)（工具按作用对象分成 6 栏，每栏对落到一侧）。

### 4.12 Agent 管理（能力启停与搜索引擎配置）

> **这一条按当前代码的**真实状态**写：**
> - **能力启停**：`GET /api/agent/tools` 能列出全部 **23 个**工具，但**当前界面没有「按需启停工具」的开关**
>   —— 已核对 `web/index.html` 全部 `<main>` 页面（创作区 / 素材库 / 硬件参数 / 本地模型配置 / 内置 Agent），
>   以及 `web/*.js` 全部 `data-act`，**没有 tool 级别的启停入口**。
>   可启停的是**两个「能力位」**：
>   1. **Provider 启停**（`#providersPage` → Provider 编辑表单「启用」勾选）—— 停用后 Agent / 增强会明确报错并指向本页；
>   2. **增强方式可用性**（按「能力契约」：Z-Image 面板看不到 Qwen 官方 PE，Qwen 面板看不到 MOSS 结构化增强）。
> - **搜索引擎配置**：**当前代码里不存在**。已全仓 + 全分支检索
>   （`search_engine` / `searchEngine` / `bing` / `serper` / `tavily` / `web_search`）**零命中**，
>   也检索了所有 `local/*` 与 `backup/*` 分支，**没有任何分支实现过**搜索引擎配置。
>   Agent 的检索能力目前是**素材库内部检索**（`search_assets` / `search_conversations` / `search_asset_history`），不是外部搜索引擎。
>
> **因此流程图不画这两条不存在的路径**，避免文档凭空造功能。
> 将来真要加，改的是：
> - 新增工具 → `h3studio/agent.py` 的 `@tool(...)` → 工具栏自动多一个节点（`gen_flow.py` 读 `TOOLS`）；
> - 新增搜索配置页 → 新增 `web/` 页面 + 后端路由 → 路由表与导航项自动进图。

### 4.13 系统配置（Provider / 增强模板 / 硬件）

- **本地模型配置**：Provider 列表 / 默认 Provider / 默认多模态 Provider / 添加 / 编辑 / 删除 / 设为默认 / 设为默认多模态 / 测试连通性。
  类型：`openai`（OpenAI 兼容）/ `ollama` / `llamacpp` / `comfyui`。
- **模板清单**：`GET /api/enhancer` 读、`PUT /api/enhancer` 存。
  **后端模板 12 个**（`h3studio/enhancer.py` 的 `TEMPLATE_SPECS`：图像 / 图像细化 / SCALIST / bbox /
  YuE2 风格 / 音乐细化 / Qwen PE 文生图 / Qwen PE 图片编辑 / MOSS-Image / 视频 / 视频导演 / 音频）

## 5. 如何重新生成

```bash
# 在仓库根目录
make flow          # = python3 scripts/gen_flow.py --render
                    #   重写 docs/交互流程图-*.mmd + .svg + .png + 派生清单

make flow-check    # = python3 scripts/gen_flow.py --check
                    #   只校验「已提交文件」与「当前代码」是否一致，不写任何文件
```

`--check` 在 CI / 提交前用，退出码非 0 表示**图已经过期**，必须重跑 `make flow` 后再提交。

### 5.1b 同步性由测试守住（不是靠自觉）

`tests/test_flow_diagram.py` 把「图 ↔ 代码一致」变成**可执行断言**：

| 测试 | 守住什么 |
|---|---|
| `test_gen_flow_check_passes` | `--check` 必须绿（图与代码逐字节一致） |
| `test_generation_modes_appear_in_diagram` | 每个后端注册的 mode，图里必须有**节点 + 连线** |
| `test_agent_tools_appear_in_diagram` | 每个 Agent 工具，图里必须有节点 |
| `test_api_routes_appear_in_derived_list` | 每条后端路由，派生清单里必须有一行 |
| `test_no_placeholder_left_in_generated_files` | 生成的 .mmd 不能残留 `@KEY@` |
| `test_no_bare_comment_line_in_generated_files` | 不能有会让 Mermaid 解析失败的裸 `%%` 行 |
| `test_rendered_artifacts_exist` | 每张源文件都要有 SVG / PNG 渲染产物 |
| `test_required_paths_are_covered` | §4 列的每条主要路径的关键内容必须在图里 |

**这组测试确实会红**（变异验证）：

- 删掉图里的 `M_t2i_moss` 节点 → `test_gen_flow_check_passes` +
  `test_generation_modes_appear_in_diagram` + `test_required_paths_are_covered` 三红；
- 在代码里注册新 mode（`BUILDERS` + `GENERATION_TYPES`）但**不重跑** `make flow`
  → `test_gen_flow_check_passes` + `test_generation_modes_appear_in_diagram` 两红。

跑法：`python3 -m pytest tests/test_flow_diagram.py -v`（11 项 + 160 个 subtests）。

| Chrome / Chromium | `mmdc` 的渲染后端 | 渲染时需要；脚本会自动找 `google-chrome-stable` 等，也可用 `PUPPETEER_EXECUTABLE_PATH` 指定 |

```bash
npm i -g @mermaid-js/mermaid-cli     # 若缺 mmdc
```

### 5.2 改流程形状（而不是改生成结果）

```bash
vim scripts/templates/flow-create.mmd     # 改骨架
make flow                                 # 重新生成
```

`docs/交互流程图-*.mmd` 是**生成产物**，文件头写明「请勿手改」；直接改它会在下次 `make flow` 时被覆盖，
并且 `make flow-check` 会立刻报「与当前代码不一致」。

### 5.3 扩展：新增一个生成模式要做什么

只改后端，前端和文档会自动跟上：

1. 在 `h3studio/workflows.py` 的 `BUILDERS` 注册构建器；
2. 在 `h3studio/gen_types.py` 的 `GENERATION_TYPES` 登记显示名 / 媒体类型 / 分类；
3. （如需素材）在 `h3studio/agent_schema.py` 的 `MODE_SLOTS` 登记槽位；
4. 跑 `make flow` —— 模式节点、模式→面板连线、派生清单三处自动更新。

实测记录：在 `BUILDERS` 与 `GENERATION_TYPES` 各加一行 `t2i_probe` 后重跑，
`docs/交互流程图-创作链路.mmd` 立刻多出 `M_t2i_probe` 节点与 `M_t2i_probe --> P_IMAGE` 连线，
`docs/交互流程图-派生清单.md` 同步多出一行；撤销改动后 `--check` 恢复通过。

### 6.1 派生失败会**报错退出**，不静默降级

`gen_flow.py` 里任何一处派生不出来（模块导入失败、模板占位符对不上、路由一条都扫不到、
模板里出现裸 `%%` 行导致 Mermaid 解析失败），都直接 `SystemExit` —— **不会**画出一张「少几个节点」的图。
理由：一张静默失真的流程图比没有流程图更糟。

### 6.2 Mermaid 语法的两个已踩坑

1. **裸 `%%` 空注释行会让 Mermaid 11.x 解析失败** —— 报
   `Parse error ... Expecting 'NEWLINE', 'SPACE', 'GRAPH', got 'NODE_STRING'`，
   后面紧跟的 `flowchart TD` 被当成节点文本。
   `gen_flow.py` 在生成阶段统一把单独成行的 `%%` 改成 `%% `，并在生成后自检。
2. **标签里的 `#` 会被当成实体转义前缀** —— 所以 `mermaid_label()` 把 `#` 换成 `＃`、`&` 换成 `＆`、
   `"` 换成 `'`、换行换成 `<br/>`。

### 6.3 派生器自己踩过的三个坑（都已修，且有回归证据）

1. **贪婪正则把两条注册项并成一条** —— 解析 `ENHANCE_METHODS` 时用「`{ ... },` 到下一个 `},`」的贪婪匹配，
   遇到嵌套对象（`write: { kind: ... }`）会串条目，**漏掉 `yue2_struct`**。
   改成**按 `id:` 字段切块**后修复 —— 现在 6 种增强方式一条不少。
2. **前端「增强方式」与后端「模板」数量不同** —— 早先图上写「模板清单（5 个）」是把前端的 5 种增强方式
   当成了后端模板数；实际后端 `TEMPLATE_SPECS` 有 **12 个**、前端增强方式有 **6 种**。
   现在两套清单分别派生、分别标注（§5 与 §5b）。
3. **模式节点写死在模板里 = 图会漏节点** —— 早先创作链路的模式节点是手写死的，
   于是「代码里新注册一个 mode」时，图里只会多一行派生清单、**图本身不出现新节点**。
   现在模式节点与模式→面板连线**都由 `gen_types.py` 派生**，
   实测（注入 `t2i_probe`）新节点与新连线同时出现，撤销后 `--check` 恢复通过。

## 8. 已知边界

- **图覆盖的是「用户操作路径 + 数据回填关系」**，不含 ComfyUI 内部的节点图（那是 `h3studio/workflows.py` 的职责）。
- **一张图里画不下全部交叉**，所以总览只画主干，横向联动写进节点文字，箭头在各子图里画。
- **Agent 工具分栏是按「作用对象」归类的**（`gen_flow.py` 的 `TOOL_GROUP_RULES`）。
  新增工具若不属于任何已有分组，会被放进「其它工具」分栏并在生成时打印提示 —— 不会丢节点。
- **派生清单里的「前端直接调用 ✅」是路径级判定**：前端字面量里不带 HTTP 方法，
  所以同一个路径上 `GET` / `DELETE` 两个路由都会标成 ✅。
